# Button
Buttons trigger immediate actions and guide people through the main flows of Proto-Typed.

## When to use
- Highlight the most important action on the screen or card.
- Guide to subsequent screens, modals, or drawers with clear context.
- Confirm submissions and save forms without ambiguity.
- Offer return paths with lighter variants (`@ghost`, `@link`).

## Basic example
<DocsCodePreview title="Main action on a task screen">
```dsl
screen Tasks:
  container:
    # My tasks
    > Prioritize the day's actions.
    row-end:
      @[Create task](TaskForm)
```
</DocsCodePreview>
Why: presents a single CTA aligned with the screen's objective.

## Variants
<DocsCodePreview title="Primary variant for main CTA">
```dsl
screen Default:
  container:
    row:
      @[Publish report](PublishReport)
```
</DocsCodePreview>
When to use: prioritize the action that moves the flow forward.
Why: highlights the main command with maximum contrast.

<DocsCodePreview title="Secondary support variant">
```dsl
screen Default:
  container:
    row:
      @secondary-sm[View history](History)
```
</DocsCodePreview>
When to use: offer a complementary option without competing with the main CTA.
Why: maintains the visual hierarchy when presenting alternative paths.

<DocsCodePreview title="Destructive variant for critical actions">
```dsl
screen Default:
  container:
    row-end:
      @destructive[Delete account](ConfirmDelete)
```
</DocsCodePreview>
When to use: signal risks and ask for confirmation before executing.
Why: associates the destructive style with high-impact actions and reduces errors.

## Composition (using with others)
- **Card + Button** — encapsulates context and keeps the CTA visible.
- **Row-end + Button** — aligns multiple actions respecting the hierarchy.
- **Modal + Button** — confirms sensitive decisions before completing tasks.

<DocsCodePreview title="Card with aligned buttons">
```dsl
screen Default:
  container:
    card:
      ## Monthly plan
      > Control recurring charges.
      row-end:
        @ghost[Cancel](-1)
        @[Update plan](UpdatePlan)
    ```
</DocsCodePreview>
Why: combines the main CTA and exit option within the same block.

## Slots & Props
| Name | Type | Default | Description | Required |
| --- | --- | --- | --- | --- |
| `variant` | enum (`@primary`, `@secondary`, `@outline`, `@ghost`, `@destructive`, `@link`, `@success`, `@warning`) | `@primary` | Defines the visual hierarchy of the action. | No |
| `size` | enum (`-xs`, `-sm`, `-md`, `-lg`) | `-md` | Adjusts the button's height and spacing. | No |
| `label` | string | — | Visible text of the button; can include an icon. | Yes |
| `icon` | token `i-` | — | Optional icon displayed before the label. | No |
| `destination` | slug/route | — | Screen, modal, drawer, action (`-1`, `close`, `alert`). | Yes |

## Common errors (Do/Don’t)
<DoDont
  dont={{
    title: "Link used as action",
    code: `
row:
  #[Send invite](ConfirmInvite)
    `,
  }}
  do={{
    title: "Button with action",
    code: `
row:
  @[Send invite](ConfirmInvite)
    `,
  }}
>
  Why: `@` executes actions in the flow; `#` is only for declarative navigation.
</DoDont>
<DoDont
  dont={{
    title: "Deletion without highlight",
    code: `
row-end:
  @[Delete account](ConfirmDelete)
    `,
  }}
  do={{
    title: "Highlighted deletion",
    code: `
row-end:
  @destructive[Delete account](ConfirmDelete)
    `,
  }}
>
  Why: the destructive variant communicates risk and reduces accidental clicks.
</DoDont>
<DoDont
  dont={{
    title: "Unclear label",
    code: `
row:
  @[Click here](DownloadReport)
    `,
  }}
  do={{
    title: "Action-oriented label",
    code: `
row:
  @[Download report](DownloadReport)
    `,
  }}
>
  Why: specific labels help quick decision-making and avoid doubts.
</DoDont>

## Cross-references

### Related
- [`Link`](./link): navigation without executing business logic.
- [`Row`](./row): organizes buttons side by side with alignments.
- [`Modal`](./modal): confirms sensitive decisions with additional messages.
- [`Navigator`](./navigator): structures alternative paths through tabs or menus.

### Recommended compositions
- **Button + Row-end** → highlights the main CTA with support actions.
- **Button + Modal** → involves confirmations before permanent changes.
- **Button + Navigator** → connects related screens in guided flows.

<DocsCodePreview title="Button with confirmation modal">
```dsl
screen Default:
  container:
    row-end:
      @destructive[Delete account](ConfirmDelete)

modal ConfirmDelete:
  card:
    # Confirm deletion
    > This action cannot be undone.
    row-end:
      @ghost[Cancel](close)
      @destructive[Delete now](deleteTenant)
```
</DocsCodePreview>
Why: combines a critical CTA with explicit confirmation to avoid errors.
