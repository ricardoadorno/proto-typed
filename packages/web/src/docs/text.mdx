# Text
Texts structure titles, paragraphs, notes, and quotes, defining the hierarchy and tone of the interface.

## When to use
- Communicate the purpose of screens with introductory titles and paragraphs.
- Highlight warnings or tips in notes (`*>`) within cards and modals.
- Record metadata or support messages with secondary levels (`>>`, `>>>`).
- Share testimonials or feedback using quotes (`">`).

## Basic example
<DocsCodePreview title="Complete textual section">
```dsl
screen ReportIntro:
  container:
    # Weekly report
    > Track the results of the last sprint.
    >> Main metrics are just below.
    >>> Updated on 09/18 at 09:30.

    card:
      *> Next review in 7 days.
      @[Open dashboard](Dashboard)
```
</DocsCodePreview>
Why: presents context, metadata, and action in clearly hierarchical blocks.

## Variants
<DocsCodePreview title="Notes and quotes">
```dsl
screen Default:
  container:
    card:
      *> Remember to validate the data before sharing.
      "> Proto-Typed reduced our prototyping time. — Squad A
```
</DocsCodePreview>
When to use: highlight alerts and record feedback with a different format.
Why: the special formatting calls attention without requiring extra components.

<DocsCodePreview title="Subtle metadata">
```dsl
screen Default:
  container:
    card:
      ## Project status
      > Complete the handoff stage today.
      >>> Updated by Ana at 10:12am.
```
</DocsCodePreview>
When to use: offer support information without competing with the main content.
Why: the `>>>` level keeps the data present, but discreet.

<DocsCodePreview title="Hierarchical titles">
```dsl
screen Default:
  container:
    # Overview
    ## Main metrics
    ### Acquisition funnel
```
</DocsCodePreview>
When to use: organize content into nested sections with clarity.
Why: a visible hierarchy helps the user to scan the page quickly.

## Composition (using with others)
- **Text + Card** — adds context and notes before actions.
- **Text + Stack** — stacks messages with controlled spacing.
- **Text + Button** — combines instruction and action in a logical sequence.

<DocsCodePreview title="Card with text and action">
```dsl
screen Default:
  container:
    card:
      ## Next delivery
      > Review the backlog with the team before the meeting.
      row-end:
        @[Open planning](Planning)
```
</DocsCodePreview>
Why: explains the context and offers the next step in a single block.

## Slots & Props
| Name | Type | Default | Description | Required |
| --- | --- | --- | --- | --- |
| `# … ####` | titles | — | Defines section hierarchy (one level-1 title per screen). | No |
| `>`, `>>`, `>>>` | paragraphs | — | Body text, small secondary text, and muted helper text. | No |
| `*>` | blockquote | — | Highlights testimonials or quoted content with a border. | No |
| `**>` | note | — | Raises critical alerts, tips, and contextual notes. | No |

<DocsCodePreview title="Callouts and quotes">
```dsl
screen Callouts:
  container:
    *> "ProtoTyped acelerou o discovery do time."
    **> Lembre-se de revisar as decisões com a equipe.
```
</DocsCodePreview>
Use blockquotes to capture testimonials and pair notes to reinforce guidance.

## Common errors (Do/Don’t)
<DoDont
  dont={{
    title: "Two `#` on the same screen",
    code: `
screen Summary:
  container:
    # Summary
    # Details
    `,
  }}
  do={{
    title: "Use of subtitles",
    code: `
screen Summary:
  container:
    # Summary
    ## Details
    `,
  }}
>
  Why: only one `#` maintains focus and prevents accessibility conflicts.
</DoDont>
<DoDont
  dont={{
    title: "Blockquote with a button",
    code: `
card:
  *> Proto-Typed speeds up deliveries. @[Learn more](Guides)
    `,
  }}
  do={{
    title: "Blockquote and action organized",
    code: `
card:
  *> Proto-Typed speeds up deliveries.
  row-end:
    @[Learn more](Guides)
    `,
  }}
>
  Why: each textual block should maintain a single purpose; actions should be in their own rows or buttons.
</DoDont>
