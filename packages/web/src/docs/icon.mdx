# Icon
Icons (`{iconname}`) reinforce the visual meaning of actions, lists, and titles without breaking the textual flow.

## When to use
- Complement buttons and links with an immediate visual cue.
- Differentiate items in lists or navigators with consistent visual clues.
- Indicate status in cards and messages without adding redundant text.
- Support FABs and highlighted actions on responsive screens.

## Basic example
<DocsCodePreview title="Icons in buttons">
```dsl
screen Shortcuts:
  container:
    # Quick shortcuts
    row-start:
      @[New task]{plus}(TaskForm)
      @outline[Export CSV]{download}(ExportCSV)
```
</DocsCodePreview>
Why: combines visual cues and text to speed up action recognition.

## Variants
<DocsCodePreview title="Icon in navigator">
```dsl
screen Default:
  container:
    # Screen content
  navigator:
    - Home | Home
    - Deploys | Deploys
    - Logs | Logs
```
</DocsCodePreview>
When to use: guide navigation with immediate clues about each tab.
Why: speeds up the identification of destinations when browsing the menu.

<DocsCodePreview title="Icon in FAB">
```dsl
screen Default:
  container:
    # Screen content
  fab{plus}(TaskForm)
```
</DocsCodePreview>
When to use: differentiate global actions in the FAB while keeping the layout clean.
Why: the icon summarizes the purpose of each action without additional text.

## Composition (using with others)
- **Icon + Button** — reinforces the CTA's intention.
- **Icon + FAB** — provides visual context for floating actions.
- **Icon + Navigator** — enhances navigation clarity.

<DocsCodePreview title="Button with icon and action">
```dsl
screen Default:
  container:
    card:
      ## Deployment status
      stack-tight:
        > Build completed
        > Tests finished
        > Monitor logs
      row-end:
        @[View logs]{eye}(ViewLogs)
```
</DocsCodePreview>
Why: buttons with icons provide clear visual cues for actions.

## Slots & Props
| Name | Type | Default | Description | Required |
| --- | --- | --- | --- | --- |
| `icon` | string `{iconname}` | — | Name of the icon available in the Lucide library. | Yes |
| `position` | inline | — | Inserted in buttons using `{icon}` syntax. | No |
| `semantics` | context | — | Choose icons that reinforce the message without ambiguity. | Yes |

## Common errors (Do/Don't)
<DoDont
  dont={{
    title: "Missing icon syntax",
    code: `
@[Export CSV](ExportCSV)
    `,
  }}
  do={{
    title: "Icon with curly braces",
    code: `
@[Export CSV]{download}(ExportCSV)
    `,
  }}
>
  Why: the `{iconname}` syntax adds the Lucide icon to the button.
</DoDont>
<DoDont
  dont={{
    title: "Icon without label",
    code: `
@[]{download}(Export)
    `,
  }}
  do={{
    title: "Icon with clear label",
    code: `
@[Export]{download}(Export)
    `,
  }}
>
  Why: the text ensures accessibility and clear communication.
</DoDont>
