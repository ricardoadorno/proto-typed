# Navigator
Navigators assemble fixed menus to quickly switch between related screens, keeping the experience aligned.

## When to use
- Build bottom navigation in mobile apps.
- Switch between main sections that share a base layout.
- Highlight up to five destinations that need to be always accessible.
- Complement simple headers when tabs or a drawer don't make sense.

## Basic example
<DocsCodePreview title="Navigator replicated on screens of the same flow">
```dsl
screen Home:
  container:
    # Home
    > Track indicators and news.

  navigator:
    - Home | Home
    - Tasks | Tasks
    - Settings | Settings

screen Tasks:
  container:
    # Tasks
    list:
      - Review backlog
      - Prepare demo

  navigator:
    - Home | Home
    - Tasks | Tasks
    - Settings | Settings
```
</DocsCodePreview>
Why: replicates the same menu on each screen of the group to ensure consistency.

## Variants
<DocsCodePreview title="Navigator with short labels">
```dsl
screen Default:
  container:
    # Screen content
  navigator:
    - Home | Home
    - Metrics | Dashboard
    - Settings | Settings
```
</DocsCodePreview>
When to use: use short, clear labels for quick navigation.
Why: reduces visual noise and favors quick reading of labels.

<DocsCodePreview title="Navigator with descriptive labels">
```dsl
screen Default:
  container:
    # Screen content
  navigator:
    - Overview | Dashboard
    - Team | Team
    - Adjustments | Settings
```
</DocsCodePreview>
When to use: provide more context with descriptive labels.
Why: helps users understand the purpose of each section.

<DocsCodePreview title="Navigator with three main sections">
```dsl
screen Default:
  container:
    # Screen content
  navigator:
    - Dashboard | Dashboard
    - Tasks | Tasks
    - Settings | Settings
```
</DocsCodePreview>
When to use: highlight the most relevant screens of a reduced flow.
Why: three items keep the focus on the essential without overloading the menu.

## Composition (using with others)
- **Navigator + Container** — keeps content aligned with fixed navigation.
- **Navigator + Screen** — applied to each screen of the group for consistency.
- **Navigator + Fab** — combines persistent navigation with a global action.

<DocsCodePreview title="Navigator with complementary FAB">
```dsl
screen Dashboard:
  container:
    # Overview
    > Use the bottom menu to navigate between sections.

  fab{plus}(TaskForm)

  navigator:
    - Dashboard | Dashboard
    - Tasks | Tasks
    - Settings | Settings
```
</DocsCodePreview>
Why: maintains fixed navigation while the FAB offers action shortcuts.

## Slots & Props
| Name | Type | Default | Description | Required |
| --- | --- | --- | --- | --- |
| `navigator` | block | — | Declares a menu with items line by line. | Yes |
| `items` | `- Label | Destination` | — | Each entry points to an existing screen. | Yes |

## Common errors (Do/Don’t)
<DoDont
  dont={{
    title: "Inconsistent menu",
    code: `
screen Home:
  navigator:
    - Home | Home
    - Tasks | Tasks

screen Tasks:
  navigator:
    - Home | Home
    - Config | Settings
    `,
  }}
  do={{
    title: "Aligned items",
    code: `
screen Home:
  navigator:
    - Home | Home
    - Tasks | Tasks
    - Config | Settings

screen Tasks:
  navigator:
    - Home | Home
    - Tasks | Tasks
    - Config | Settings
    `,
  }}
>
  Why: consistency prevents the person from losing destinations when switching screens.
</DoDont>
<DoDont
  dont={{
    title: "List used as a menu",
    code: `
  - Dashboard
  - Tasks
  - Settings
    `,
  }}
  do={{
    title: "Menu with navigator",
    code: `
navigator:
  - Dashboard | Dashboard
  - Tasks | Tasks
  - Settings | Settings
    `,
  }}
>
  Why: `navigator` applies appropriate semantics and behavior for menus.
</DoDont>

- **Navigator + Drawer** → bottom menu + side panel for extra context.

<DocsCodePreview title="Navigator and drawer combined">
```dsl
screen Projects:
  container:
    # Projects
    list:
      - New website
      - Mobile application

  navigator:
    - Projects | Projects
    - Team | Team
    - Settings | Settings

drawer Filters:
  container:
    # Filter projects
    ___[Status][Select status[All | Active | Completed]]
    row-end:
      @[Apply filters](applyFilters)
```
</DocsCodePreview>
Why: navigator handles global navigation while the drawer filters the current content.
